# 审查核实与修复（2026-09-16）

本次针对实际运行问题修复，保留五轮盲测及权限边界；未将所有工程建议当作缺陷。

## 已确认并处理

| 审查项                | 核实与处理                                                                                                                                                                                                                               |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 静态资源缓存          | 两层 `no-store` 确实覆盖 Next 静态资源。两层均排除 `/_next/static/`，由 Next 管理生产 immutable 缓存与开发缓存；页面/API 仍不缓存。生产 HTTP 验证逐个检查 JS/CSS 的响应头。                                                              |
| 游戏轮询写事务        | `getPlayHome` / `getPlayRoom` 原先确实取得全局 advisory lock 并更新过期房间。改为一致快照读取，复用相同过期条件，历史/统计同步显示逻辑取消；下一次写入持久化过期。回归测试实际持有全局锁，证明两个读取不被阻塞且未写库。写入原子锁保留。 |
| AI 回复预算与瞬时失败 | 原来的 600 字上限与 400 token 预算不匹配。改为 120 字/512 tokens；截断重试改为 60 字/768 tokens。暂时网络错误、部分暂时 HTTP 错误和截断最多重试一次，总时限 Ollama 75 秒/兼容接口 45 秒，支持外部取消。不接受截断、推理或工具输出。      |
| 限流桶满拒绝新用户    | 10,000 个精确桶满后原先无条件拒绝新 key。新增 1,024 个有界共享溢出桶，不淘汰仍活跃的精确计数；容量恢复保留消耗额度，并限制清扫频率。共享桶碰撞会保守限流，持续洪泛仍需部署层的可信连接/IP 限流。                                         |
| 生产启动缺少依赖      | `npm start` 所需 `tsx` 原来仅在开发依赖。将 `tsx` 和 migration 服务所需 Prisma CLI 列为运行依赖，Docker 构建后剔除开发依赖并仅复制运行文件。保留 TS 自定义服务启动方式，未误用不包含自定义服务器的 standalone 产物。                     |
| 生产 CSP              | 生产移除 `unsafe-eval`，WebSocket 允许地址由 `APP_ORIGIN` 派生。当前 Next 内联启动脚本仍需要 `unsafe-inline`，未声称实现 nonce CSP。                                                                                                     |
| 过期查询索引          | 新 migration 添加 `AuthSession.expiresAt` 及 `Generation(status, triggeredAt)` 索引，匹配现有过期清理查询。                                                                                                                              |
| 验证覆盖遗漏          | 新增 `test:all` 自动包含全部测试文件，README 补齐 play/evaluation；GitHub Actions 使用临时 PostgreSQL 执行类型检查、全部测试、构建、去除开发依赖后生产 HTTP 验证。Compose 添加就绪 healthcheck。                                         |

项目建立独立 Git 仓库，公开源码与实现文档；环境文件、数据库、模型、构建缓存及原始研究输入均不提交。
