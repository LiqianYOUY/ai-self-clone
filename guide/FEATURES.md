# 功能与使用边界

项目包含五轮文字盲测游戏、三端真人聊天准备区和合成研究演练。三类数据相互隔离：游戏不读取或写入研究语料及准备聊天，准备区不产生正式实验会话、分身语料或评价记录。

完整在线版可让参与者直接在浏览器注册、邀请和进行真实多人及 AI 聊天，无需在参与者电脑运行终端。服务端需要 Node.js、PostgreSQL 与模型服务，GitHub Pages 只展示入口。树莓派部署进度及已验证范围见 [VERIFICATION.md](VERIFICATION.md)，安装与使用见 [README](../README.md)。

## 五轮文字盲测

### 页面和流程

- `/`：游戏介绍和主要入口；原三个门户作为次要入口。
- `/play`：主持人注册/登录、分身档案、上线、邀请、本人回复台、统计。
- `/play/join#token=…`：朋友邀请预览、昵称与玩法说明。页面读取邀请后清除地址栏令牌。
- `/play/room/[id]`：朋友五轮文字聊天、猜测和揭晓。

朋友不用账号。一次性邀请换取绑定房间的 HttpOnly cookie，原始邀请令牌不存入数据库。主持人复用 Target 账号会话；自助注册的游戏账号不自动加入研究名单。

每局由服务端等概率选择 HUMAN/AI，并保存分身资料快照。朋友先问、来源后答，累计五组完整对话后可提交猜测。刷新不会重抽身份；同一消息的网络重试不会重复入库；重复猜测不会改写答案。消息和结果由 Postgres 持久保存。

主持人一次只开放一个未结束的房间，游戏页面每十秒发送在线心跳。离线达到服务端阈值、取消、超时或模型失败都会取消房间，晚到的模型输出不能重新激活房间。取消的局不计入识别率。

### 分身材料

从一页个人资料和约三十组精选对话开始。对话示例建议写成“朋友：…… / 我：……”并保留当时上下文、标点和表情习惯。共同经历只填可以用于游戏的事实；模型被要求在无依据时自然表达不确定。

保存时会解析本人和朋友的发言，将本人的原话、真实接话关系、句长分布、表情/问号/感叹号/句末标点频率，以及带样本依据的反复表达保存为版本化风格档案。归纳发生在证据与提示层，由模型参照原话和表达习惯生成，不训练或更新基础模型权重，不等同于模型参数蒸馏或微调。示例中使用不同称呼时，在“示例中你的称呼”明确指定本人；无法识别本人时仍可保存草稿，但不能试聊或创建实验邀请。

主持人可检查识别对象、样本数量和提炼结果，再进行最多五轮的私有试聊。试聊不会保存到账号，不创建实验房间、消息或结果；只有主持人亲自填写并点击加入的纠正会进入资料草稿，保存后才用于新局。AI 生成的回答不会自动成为学习材料。至少八条本人发言、三组接话会显示“示例较充足”，这只是材料数量提示，不代表模仿准确率。

生成时按当前消息的场景、语言和文字重合选取最多四个相关示例，区分问候、请求澄清、质疑语气及情绪倾诉，避免跨场景套用。只有“老地方”“那就”等省略了前文信息的承接语会尝试沿用先前话题；没有相关参考时，不塞入通用旧例，而是依据本人表达习惯和本局内容回答。

请求澄清时，参考只保留本人原话里实际出现的解释开头，例如“我没说清楚”，不带入历史事件的原因，也不补造本人没说过的开头。解释的后半句须依据本局对话，优先定位上一句和朋友引用的内容；仍有多个可能对象时再反问。提示区分本人和朋友的代词归属，先前回复可以更正，未说过的原因无需补充；人物往事保留原有时间，旧例中的经历不作为本局事实。

场景规则覆盖“工作压得喘不过气”“脑子转不动”及英文 overwhelmed 等压力表达，并对定义或翻译提问、否定压力的说法和 overwhelmed with joy 等正向表达设置过滤，减少误触发安慰式接话。这是有限规则匹配，不是完整的语义或情绪识别。明确的“对吧”等确认问句会优先核对本局已说明的内容，可确认、纠正或保留未知；这个提示分支不改变示例检索，也不是事实校验器。

房间固定资料、风格档案、提示词版本及配置的模型标识，保存修改不会改变已有房间；版本或模型变化时不允许在原房间静默切换。旧资料无需批量改写，重新保存会持久化新档案。

仅使用专门填写在游戏中的材料，不自动导入已有私聊或研究数据。朋友进入时会看到游戏包含 AI，以及聊天由本人或配置的模型处理的说明。默认使用本机模型，不将聊天内容发送到云端服务。

### 模型配置

本机模型模式无需 API 密钥：运行 `npm run model:setup` 一次，默认下载项目内 Ollama 和 Qwen3.5 4B；树莓派通过 `PLAY_MODEL_NAME` 改用 0.8B，见 [部署说明](DEPLOYMENT.md)。以后 `npm run dev` 自动启动已安装的本地运行时，退出时只关闭由本项目启动的进程。也可用 `npm run model:start` 单独启动。模型准备后，主持人页面会自动检测模型是否就绪。

macOS 便携运行时固定为 Ollama v0.33.3，下载后核验 SHA-256；优先复用已安装的 Ollama。项目自行启动服务时禁用云端功能，只绑定本机地址。参考 [Ollama 原生聊天接口](https://docs.ollama.com/api/chat) 和 [Qwen3.5 4B](https://ollama.com/library/qwen3.5:4b)。模型约 3.4GB；首次安装需联网，后续聊天在本机处理。小模型是否像本人需要真实样本与试玩验证。

本机可通过 `.env` 修改默认值；线上部署应在服务端环境或托管平台的密钥配置中设置：

| 变量                  | 用途                                                                   |
| --------------------- | ---------------------------------------------------------------------- |
| `PLAY_MODEL_PROVIDER` | 默认 `ollama`，可显式设为 `compatible` 接其他接口                      |
| `PLAY_MODEL_BASE_URL` | 默认 `http://127.0.0.1:11434`；兼容模式填 API 根地址，包括必要的 `/v1` |
| `PLAY_MODEL_API_KEY`  | 本地 Ollama 不需要；兼容模式需要，只保存在服务端                       |
| `PLAY_MODEL_NAME`     | 默认 `qwen3.5:4b`，也可用已下载的其他本地模型                          |
| `PLAY_MODEL_RESIDENT` | 默认关闭；设为 `1` 时在本地启动前预热模型并保持内存驻留                |

Ollama 模式只允许本机地址，拒绝云端模型别名，使用原生 `/api/chat` 并关闭 thinking；兼容模式使用非流式 `/chat/completions`，远程地址要求 HTTPS。两种接口使用温度 `0`，减少相同资料与上下文下的随机漂移；这不保证跨硬件逐字一致或事实正确。单次请求时限分别为 60 秒和 30 秒；临时网络、部分临时 HTTP 错误、截断或明确风格、语义违例合计最多重试一次，总时限分别为 75 秒和 45 秒。回复长度由本人示例的九十分位数和消息场景决定，并按 Unicode 字素实际校验；短句资料通常上限 24 字符，招呼最多 40，长表达最终不超过 600。512 tokens 是生成预算，不当作汉字长度；截断重试最多 60 字符且使用 768 tokens。

无表情证据时拒绝擅加图标，无动作证据时拒绝典型舞台动作。有限的语义规则还会检查澄清、倾诉和质疑场景中的复读；本人样本数量与典型句长足够时，检查只有“嗯”“好的”等应声、没有接住意思的回复。朋友在问是非问题，或同场景真实示例支持该短答时，不因此拒绝。违例重写只追加纠正要求，不把失败回复加入对话，也不保证其他语义错误都能被发现。不记录请求正文或供应商错误内容。此接口独立于正式研究 provider，配置它不会启用正式研究。

专用本机服务可显式设置 `PLAY_MODEL_RESIDENT=1`：`start-local` 在启动应用前发送不含任何对话的空请求，预热配置的模型，独立时限为 180 秒；失败或取消时不会继续启动应用。后续本机回复通过 `keep_alive=-1` 保持驻留，避免闲置后再次冷加载，占用相应模型内存。未开启时仍保留十分钟，兼容接口不受此开关影响；直接运行 `npm start` 不执行监督器预热。参考 [Ollama 预热与驻留说明](https://docs.ollama.com/faq)。

模型未就绪时主持人可登录和整理资料，创建邀请会被阻止。模型错误向朋友统一呈现为本局结束，不用固定话术冒充真实 AI 结果。自动化测试使用模拟的供应商响应，不消耗外部模型额度。

### 游戏验收规则

- 服务端等概率选定本人或 AI，刷新、消息重试与并发请求不能改变来源或顺序。
- 五组完整问答之后才能猜测；猜测前朋友 DTO 不含 mode、模型名称、分身资料、答案或账号凭证。
- 朋友不能访问其他房间或调用主持人回复入口。离线、取消或停止后的模型回调不能重新进入聊天记录。
- AI 误判率 = AI 局猜本人的次数 / 已揭晓 AI 局数；本人识别率 = 本人局猜本人的次数 / 已揭晓本人局数。取消局不计入，无样本显示空值。

## 三端真人聊天准备区

准备区提供账号、邀请、个人资料、同意和真人双方通信，AI 不自动回复。

### 入口与权限

| 页面                              | 用途                                    | 身份来源                                    |
| --------------------------------- | --------------------------------------- | ------------------------------------------- |
| `/research`                       | 成员与邀请管理；分析员只读进度          | 首个研究员本机初始化，分析员由研究员邀请    |
| `/research/join#token=…`          | 分析员邀请注册                          | 固定 ANALYST 角色                           |
| `/research/sandbox`               | 原研究流程演练                          | 已认证 Researcher / Analyst，保留原权限差异 |
| `/target`、`/target/join#token=…` | Target 登录、注册、好友邀请、聊天及资料 | 研究员生成的单次 Target 邀请                |
| `/friend`、`/friend/join#token=…` | Friend 登录、注册及与邀请人聊天         | Target 生成的单次 Friend 邀请               |
| `/demo`                           | 原合成角色演练工具                      | 本机演练授权，独立 Cookie                   |

真实三端不能通过切换下拉框改变身份。三种 Cookie 名称分别是 `clone_research_session`、`clone_target_session`、`clone_friend_session`，可以在同一浏览器并存。HTTP 请求通过 `x-study-portal` 指定读取哪个会话，服务器校验 token 对应的持久门户与角色，不能靠修改 header 获得另一身份。Cookie 为 HttpOnly、SameSite=Strict，在 HTTPS origin 下增加 Secure，8 小时过期。数据库只保存 session token 散列。

### 注册与邀请

首次本机启动且 Account 为空时，可设置首个研究员；需要 `PORTAL_BOOTSTRAP_ENABLED=true`、loopback host 和 origin。`npm run dev` 默认仅为本机开启该配置，独立启动应用时必须显式配置。初始化与所有邀请消费使用数据库事务锁，多个同时请求只能创建一个首个研究员。

用户名 3–40 位，使用字母、数字、点、下划线、短横线且首字符为字母或数字；统一小写后唯一。密码 12–128 位，使用独立随机盐的 scrypt。显示名称 1–40 位，不要求联系方式。没有默认管理密码，没有预建真实账号。

研究员可以邀请 Target 和分析员；Target 只能邀请自己的 Friend。邀请由安全随机令牌生成，数据库只存 SHA-256 散列，7 天有效、单次消费、可在接受前撤销。每个 Target 最多三份已接受或当前有效待接受的 Friend 邀请，数量在事务中校验。邀请接受后自动建立该 Target 与 Friend 的唯一准备聊天室。

链接使用 `#token=`，浏览器读取后清除地址栏中的 token，预览以 POST 发送。完整链接仅在创建后的当前页面显示，刷新后可查看状态和撤销，但不能重新获取原始 token。系统不发送邮件或站外消息，由邀请人复制并自行分享。

### 参与说明和聊天

参与者独立确认版本 `enrollment-v1` 的聊天准备区说明。仅授予本准备区参与权限；AI 处理、分身语料、逐字引用、二次分享等研究授权默认为 false，后续正式研究必须单独征求。

聊天使用 PreparationRoom / PreparationMessage，真实双方通信，AI 不自动回复。准备区不写入正式 Session、Message、CorpusItem、PersonaVersion 或任何评价表。研究端仅查看成员和聊天室状态/数量，不读取聊天正文。消息保存在部署实例的 PostgreSQL，界面每 2 秒从经权限校验的 API 更新当前房间。

消息最多 4000 字符，服务端按房间顺序编号。每位发送者的幂等键使网络重试不重复创建消息；相同键改内容会被拒绝。只有双方当前参与同意有效且房间 ACTIVE 才能发送。任一方可以暂停，只有暂停者可以继续；任何一方可结束，ENDED / WITHDRAWN 不能重开。

暂停参与会立即阻止消息发送并隐藏聊天正文，恢复同意后仍需按房间暂停者权限继续。退出保留账号用于查看参与状态，同时撤销同意、使聊天室退出、撤销待接受好友邀请。选择删除时，清空相关准备聊天室双方的正文并写入删除墓碑；数据库触发器阻止删除后的正文再次写回。必要的账号、审计及删除记录保留。此操作不承诺清除独立数据库备份。

### 接口

统一入口 `/api/portal`，所有请求携带 `x-study-portal: research|target|friend`，身份仅从对应 Cookie 读取。写请求使用同源 JSON，严格校验字段、收到的实际字节长度、频率和 CSRF。

- GET：`view=me`、`home`、`rooms`、`room&id=…`。
- POST：`{ action, payload }`。
- 未登录操作：`bootstrap`、`login`、`register`、`inspectInvitation`。
- 管理操作：`invite`、`revoke`、`profile`、`logout`。
- 聊天操作：`send`、`pause`、`resume`、`end`。
- 数据权利：`consent`、`withdraw`。

真实 Target / Friend 无法使用旧 `/api/study` 操作；即使伪造 header 或复制 Cookie，也无法将真实账号降级为演练身份。原研究演练的成员计数、同意、审计、撤回与导出只处理合成研究范围。

## 合成研究演练

演练种子包含 12 位 Target、36 位 Friend、36 个 dyad 和 216 场计划会话，包含已完成、活动和安全暂停状态。合成账号切换仅在本机或受访问码保护的演练环境开放，不可作为正式身份认证。

| 角色   | 可操作的研究演练流程                                                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 研究者 | 概览、会话启动/暂停/结束、研究状态、安全事件确认与处置、数据导出与审计、冻结分配报告                                                                          |
| Target | 自己的语料导入与逐条隐私审查、BUILD/DEV/HOLDOUT 分区、校准回答、表达档案构建与冻结、DEV 预览、仅记录时间的独立练习、本人 Human 会话、关系测量、独立同意与撤回 |
| Friend | 中性聊天、跳题/暂停/结束/退出、来源质询提示、可跳过的会话评价、独立 offline 片段评价、逐片段授权、匹配评价与生态观察、关系测量、自愿解释与来源揭示            |
| 分析员 | 经掩码的结构化导出、去正文审计、评价数量与研究状态；不能读取联系人或任意聊天正文                                                                              |

合成 provider 的固定规则回复用于验证工作流，不代表真实语言模型质量。正式研究模式仍阻断，修改环境变量或填入模型密钥不能单独启用。Anthropic adapter 仅有结构及 mock 测试，未记录真实供应商联调。

## 运行范围

本地默认地址为 `http://127.0.0.1:3000`，默认邀请链接也只在本机可达。异地朋友使用完整服务需要实际可达的 HTTPS 部署、正确 `APP_ORIGIN` 和运行配置。机构 SSO、邮件邀请及账号找回未连接；首次注册没有默认管理员密码。项目不会自动发送站外消息。

验证命令、历史结果和模型测试范围统一记录于 [VERIFICATION.md](VERIFICATION.md)。正式研究的批准项、数据删除与恢复边界见 [ARCHITECTURE.md](ARCHITECTURE.md)。
