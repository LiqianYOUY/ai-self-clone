## 执行检查

安装依赖后，使用独立临时 PostgreSQL 检查：

```bash
npm run typecheck
npm run test:isolated
npm run build:isolated
PORTALS_SMOKE_BUILD_DIR=.cache/production npm run test:isolated -- verify:production test:portals:http
```

`test:isolated` 默认执行 `test:all`，自动包含 `tests/*.test.ts` 中全部套件，覆盖领域规则、HTTP 网关、门户认证、数据库内核、二级评价、准备区与五轮游戏。临时数据库结束后清理，不连接现有 `.local` 数据库；已有独立测试数据库时也可直接运行 `test:all`。

需要检查特定运行路径时：

| 检查                 | 命令与前提                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| HTTP / Socket.IO     | `npm run test:runtime`，需要应用和数据库运行                                                              |
| 角色页面与越权路径   | `node --import tsx scripts/testing/smoke-navigation.ts`，需要应用和数据库运行                             |
| 准备区 HTTP          | `PORTALS_SMOKE_BUILD_DIR=.cache/production npm run test:portals:http`，使用生产构建和临时 schema          |
| 真实本地模型五轮游戏 | `node --import tsx scripts/testing/smoke-play.ts`，需要生产构建、数据库与 Ollama；临时 schema 和端口 3305 |

生产验证通过临时回环服务检查健康、页面与 API 不缓存、JS/CSS immutable 缓存、CSP、RSC、未经授权的 API，以及服务器源码、环境文件和数据库密码路径不可访问。构建产物检查已知合成身份、正文和分配 seed，并拒绝公开浏览器 source map；这不是对任意敏感信息的完备证明。

## 已核实的缺陷修复（2026-09-16）

| 问题                           | 修复及验证                                                                                                                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 静态资源缓存失效               | 两层 `no-store` 排除 `/_next/static/`，静态文件缓存交由 Next 管理；页面/API 仍不缓存。生产验证逐个检查 JS/CSS 响应头。                                                                                 |
| 游戏轮询取得全局写锁           | `getPlayHome` / `getPlayRoom` 改为一致快照读取，按相同过期条件显示逻辑取消，下一次写入持久化过期。回归测试持有全局锁，确认读取不阻塞且未写库；写入原子锁保留。                                         |
| 正常游戏房间从主持人页面消失   | 取反的过期条件在 `pendingSince = NULL` 时受 SQL 三值逻辑影响，使正常房间的 `activeRoom` 返回 null。超时条件显式增加 `not: null`，并回归 HUMAN/AI 等待、聊天及回复前后的生命周期。                      |
| 启动失败和数据库退出后无法恢复 | 启动监督进程保留失败退出码，将子进程被信号终止视为失败，监听自有数据库意外退出以触发 systemd 重启；统一清理自有进程，避免退出钩子覆盖失败状态或等待已退出进程。自动测试及 Pi 恢复演练通过。            |
| AI 输出预算不足和瞬时失败      | 普通回复上限改为 120 字 / 512 tokens；截断重试要求 60 字 / 768 tokens。临时网络、部分临时 HTTP 错误和截断最多重试一次，总时限 Ollama 75 秒、兼容接口 45 秒，支持外部取消；不接受截断、推理或工具输出。 |
| 限流桶满后拒绝所有新 key       | 10,000 个精确桶外增加 1,024 个有界共享溢出桶，不淘汰活跃计数；容量恢复时保留消耗额度并限制清扫频率。碰撞会保守限流，部署层仍需可信连接/IP 限流。                                                       |
| 生产依赖不完整                 | `tsx` 和迁移所需 Prisma CLI 列为运行依赖；Docker 构建后剔除开发依赖并仅复制运行文件。保留自定义 TS 服务启动，不误用不包含自定义服务器的 standalone 产物。                                              |
| 生产 CSP 过宽                  | 移除 `unsafe-eval`，WebSocket 地址由运行时 `APP_ORIGIN` 派生。Next 内联启动脚本仍需要 `unsafe-inline`，尚未实现 nonce CSP。                                                                            |
| 过期清理缺少索引               | migration 增加 `AuthSession.expiresAt` 和 `Generation(status, triggeredAt)` 索引。                                                                                                                     |
| 测试入口漏掉套件               | `test:all` 统一收集全部测试；CI 模板包含临时 PostgreSQL、类型检查、全部测试、构建及剔除开发依赖后的生产验证。Compose 增加就绪检查。                                                                    |

整理部署前的修复版本记录为 108 项自动化测试、TypeScript、生产构建、六个 migration、生产 HTTP 与仅安装生产依赖的启动检查通过；当前版本结果见上方。自动化模型回归使用模拟响应，没有向外部模型发送研究资料。

GitHub Actions 模板保存在 [`deploy/github-actions-ci.yml`](../deploy/github-actions-ci.yml)，需要具有 `workflow` 权限的发布凭据才能安装到 `.github/workflows/ci.yml`。模板存在不代表远程 CI 已执行。

以下审查建议没有被当作已证实的缺陷：

- 最终模型失败后取消整局符合五轮盲测规则；重试耗尽后仍取消，不伪造回复、切换来源或把不完整对局计入结果。
- 读取全局锁已移除，但没有负载测试证明剩余写入争用或给出容量上限。
- `next lint` 不适用于此项目的 Next.js 16 CLI。格式统一、ESLint、组件拆分和其他性能重构需要独立依据。
